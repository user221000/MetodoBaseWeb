  <header>
    <h1>OpenSSL 3.5 Series Release Notes</h1>
    
    
    
  </header><p>The major changes and known issues for the 3.5 branch of the
OpenSSL toolkit are summarised below. The contents reflect the current

git repository.</p>

<h2 id="major-changes-between-openssl-34-and-openssl-350-8-apr-2025">Major changes between OpenSSL 3.4 and OpenSSL 3.5.0 [8 Apr 2025]</h2>
<p>OpenSSL 3.5.0 is a feature release adding significant new functionality to
OpenSSL.</p>
<p>This release incorporates the following potentially significant or incompatible
changes:</p>
<ul>
<li>
<p>Default encryption cipher for the <code>req</code>, <code>cms</code>, and <code>smime</code> applications
changed from <code>des-ede3-cbc</code> to <code>aes-256-cbc</code>.</p>
</li>
<li>
<p>The default TLS supported groups list has been changed to include and
prefer hybrid PQC KEM groups. Some practically unused groups were removed
from the default list.</p>
</li>
<li>
<p>The default TLS keyshares have been changed to offer X25519MLKEM768 and
and X25519.</p>
</li>
<li>
<p>All <code>BIO_meth_get_*()</code> functions were deprecated.</p>
</li>
</ul>
<p>This release adds the following new features:</p>
<ul>
<li>
<p>Support for server side QUIC (RFC 9000)</p>
</li>
<li>
<p>Support for 3rd party QUIC stacks including 0-RTT support</p>
</li>
<li>
<p>Support for PQC algorithms (ML-KEM, ML-DSA and SLH-DSA)</p>
</li>
<li>
<p>A new configuration option <code>no-tls-deprecated-ec</code> to disable support for
TLS groups deprecated in RFC8422</p>
</li>
<li>
<p>A new configuration option <code>enable-fips-jitter</code> to make the FIPS provider
to use the <code>JITTER</code> seed source</p>
</li>
<li>
<p>Support for central key generation in CMP</p>
</li>
<li>
<p>Support added for opaque symmetric key objects (EVP_SKEY)</p>
</li>
<li>
<p>Support for multiple TLS keyshares and improved TLS key establishment group
configurability</p>
</li>
<li>
<p>API support for pipelining in provided cipher algorithms</p>
</li>
</ul>
<p>Known issues in 3.5.0</p>
<ul>
<li><a href="https://github.com/openssl/openssl/issues/27282">https://github.com/openssl/openssl/issues/27282</a>
Calling SSL_accept on objects returned from SSL_accept_connection
results in error.  It is expected that making this call will advance
the SSL handshake for the passed connection, but currently it does not.
This can be handled by calling SSL_do_handshake instead.  A fix is planned
for OpenSSL 3.5.1</li>
</ul>
