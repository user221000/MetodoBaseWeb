La auditoría OS está pendiente. El inventario del contenedor base muestra Debian 13 (trixie); la auditoría de las distribuciones Python no cubre estos paquetes.

El siguiente trabajo usará el ejecutable portable Linux/amd64 de Trivy 0.76.0, sin instalarlo en Windows ni en el producto. La [release primaria](https://github.com/aquasecurity/trivy/releases/tag/v0.76.0) es inmutable según su API. El asset `trivy_0.76.0_Linux-64bit.tar.gz` tiene 52 253 735 bytes y SHA256 `e24b1c51293c1b15e4ba8d45bbc7891ba053f90278ec2698f3562c993e145fe7`, coincidente entre la API de la release y su archivo de checksums primario. `os-audit-plan-primary/plan-pins.json` conserva URLs, IDs y hashes. Este paso obtuvo metadata y checksums; todavía no descargó ni ejecutó el scanner.

Antes de ejecutarlo se descargarán el asset y su bundle Sigstore de esas URLs exactas. Se verificará SHA256 y después la firma mediante una copia de Cosign con procedencia verificada, emisor `https://token.actions.githubusercontent.com` e identidad exacta `https://github.com/aquasecurity/trivy/.github/workflows/reusable-release.yaml@refs/tags/v0.76.0`. La [documentación primaria de firma](https://trivy.dev/docs/latest/getting-started/signature-verification/) describe este mecanismo. Un checksum coincidente no se presentará como firma verificada.

La ejecución ocurrirá dentro del guest propio contra el ID inmutable de la imagen final, sin arrancar su aplicación. El contrato es `trivy image --scanners vuln --pkg-types os --image-src docker --format json --output <evidencia.json> <image-id>`, con cache propia. Se registrarán versión/hash del ejecutable, comandos, exit code, salida íntegra, metadata y fecha de actualización de la base de vulnerabilidades, digest de la imagen OCI de esa base, hashes de sus archivos locales y el ID de imagen examinado. Tras descargar una base concreta, se repetirá el análisis con esa misma base y `--skip-db-update` para comprobar la reproducción del resultado. No se filtrarán CVEs ni se aceptarán silenciosamente errores de análisis o distribuciones no soportadas.

Se contrastarán los hallazgos Debian con sus avisos y versiones de paquetes del proveedor. La [documentación primaria del alcance OS](https://trivy.dev/docs/latest/scanner/vulnerability/) explica el uso de avisos del fabricante y la exclusión de binarios compilados fuera del gestor de paquetes. CPython instalado bajo `/usr/local`, sus componentes incorporados y el código de la aplicación requieren revisión separada. Una versión upstream de OpenSSL por sí sola tampoco demuestra el estado de parches de un paquete Debian.

El cierre exigirá inventario OS completo, correspondencia de paquetes analizados, hallazgos íntegros y tratamiento documentado de cada excepción. Hasta entonces no existe aceptación de seguridad OS. El cambio de base también requiere suites Linux sobre Python 3.12.15 y pruebas posteriores de arranque, readiness y PostgreSQL; esas pruebas no forman parte del inventario ni de la SCA de paquetes.
