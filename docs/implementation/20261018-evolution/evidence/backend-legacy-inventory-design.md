# Legacy document inventory: read-only boundary

The tool inventories references rather than authorizing migration. Every entry is `review_required`, including a unique file with a plausible PDF header or decoded logo, correct size and stable SHA256. Historical filenames may have been overwritten; a database row cannot establish whose bytes survived. No apply/PUT, DDL, association update, cleanup, source rename or deletion is implemented.

The service is `web/services/legacy_object_inventory.py`; the CLI is `scripts/inventory_legacy_objects.py`. It never imports application credentials/settings or reads `.env`. The database URL comes from the explicitly named `LEGACY_INVENTORY_DATABASE_URL` environment variable (or `--url-env`), and `--expected-database` must match. PostgreSQL requires explicit host, user and database; libpq authority/query overrides are rejected, with a small TLS-only allowlist. SQLite requires an existing absolute source path and opens URI `mode=ro`. Roots and destination are validated before constructing an engine or connecting. There is no fallback to `DATABASE_URL`. The private report fingerprints the database identity without serializing its URL, credentials or absolute SQLite path.

First rehearse on an isolated restored copy. No production database was accessed by this work. PostgreSQL uses one dedicated REPEATABLE READ / READ ONLY transaction for both passes, requiring an already-existing globally visible operational role (`rolsuper` or `rolbypassrls`). Catalog checks are schema-qualified, including a negative test with a spoofed public catalog table and adverse search path. The tool neither creates such a role nor changes RLS/helper functions. The application role fails before emitting a global inventory. SQLite uses explicit BEGIN plus `query_only`; its CLI file connection is physically read-only. The tool rolls back its read snapshot on exit.

Plans are paged by primary-key keyset, with their clients joined by client identity and the gym IDs compared explicitly. Missing clients, mixed tenant links, soft-deleted plans and clients are classified. GymProfile logos are paged separately. New object references are excluded from entries and file reads. Their remaining legacy path values still participate in duplicate detection: they can be evidence of a historical overwrite affecting another legacy row. Deleted and otherwise invalid rows also contribute to that index. Both same-owner and cross-owner repetitions are ambiguous; no winner is selected.

The first pass holds only normalized absolute path SHA256/count pairs, using the host's `normcase`, with an explicit default ceiling of 100,000 distinct paths. The configurable technical maximum is one million. Exceeding it returns an error and closes the private JSONL with `complete=false`; it never reports a completed inventory. The second pass writes entries individually. A complete footer means the selected database snapshot's references were covered, not that every file was readable or that the report is valid for later writes. Concurrent rows committed after the snapshot are intentionally outside that coverage.

PDF roots must be explicit absolute directories outside known public static trees. The explicit logo root must end at the actual legacy `web/static/uploads/logos` directory; only URLs below `/static/uploads/logos/` map into it. Traversal, foreign-platform path syntax, symlinks/junctions, paths outside roots, missing/non-regular/empty/oversized files and wrong types are rejected. Ambiguous or invalid database associations are recorded without opening their bytes; their size/SHA fields remain NULL. Unique eligible candidates are read in bounded chunks, comparing fd/path identity, size and nanosecond times before/after. The final open handle is checked on Windows and on systems exposing `/proc/self/fd`; path reparse checks also run around the read. File changes are classified, never repaired. A local Windows probe found differing ctime values between Path.stat and os.fstat on 33 of 150 stable files; cross-API comparison therefore uses device/inode/size/mtime, while full ctime remains compared before/after separately within each API. The deterministic regression failed before that correction and preserves rejection of actual fd-ctime changes.

PDF inspection checks the extension and PDF magic header, not complete PDF semantics or historical origin. Logos are decoded with the existing bounded 2-MiB/16-megapixel/single-frame normalizer, but normalized bytes are discarded: source bytes and metadata are unchanged, and the recorded digest belongs to the source. A later apply must normalize the approved logo again and distinguish source and destination digests.

The manifest is created exclusively, outside source roots and the repository, in an explicit existing private directory. POSIX requires a directory without group/other permissions and creates the file with mode 0600. Windows requires the operator to supply a directory with restricted ACLs; Python mode bits do not attest Windows ACL policy. Manifest entries deliberately contain tenant/row identifiers and relative legacy names, so the artifact is private and must not be committed or published. Absolute source roots are represented only by fingerprints. Credentials/URLs and file contents are absent. CLI output/errors contain only counters and stable codes/classes; argparse never echoes bad values. The implementation has no source-path/data logger.

## Subsequent apply contract, deliberately not implemented

An apply needs reviewed provenance for each row, bound to the inventory format, source database/revision, root fingerprints, row/source fingerprint, original byte SHA256 and an authenticated approval artifact. `complete=true` or an unmodified JSONL is insufficient. Ambiguous, missing, mixed or deleted cases stay unresolved until independent evidence establishes ownership; the program must not choose a row to retain or assign another subject's bytes.

Before publication it must re-read the exact source under an agreed writer/maintenance boundary, re-check all normalized references globally for new duplicates and verify the file again. A database snapshot and CAS alone cannot freeze filesystem writers or prevent a new duplicate path in another transaction. A reviewed serializable/advisory-lock protocol or an explicit quiescence window is still needed, including host path/case mapping on restored systems. The current inventory does not supply that coordination.

The final association must lock and compare the canonical row: owner, same-owner client, deletion state, original legacy value, NULL new reference and the source fingerprint. It must also revalidate the subject's eligibility instead of deriving authority from filenames. Publish a stable, durable pending descriptor before PUT; after successful byte integrity checks, mark ready and attach the reference in the same transaction with a conditional update that affects exactly one expected row. A failed CAS must not attach, grant rights, delete originals or automatically clean an uncertain object.

Idempotent resumption needs a durable reviewed mapping/journal from the source row plus approved fingerprint to one pending descriptor. The current StoredObject schema does not have that migration source key. An approved journal/schema design and conflict/uncertain-PUT reconciliation remain necessary before implementing apply. Neither object publication nor its retry can establish historical provenance. Retention, orphan cleanup and deletion of legacy originals remain separate decisions.
