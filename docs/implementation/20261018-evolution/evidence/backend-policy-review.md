# Revisión independiente backend de R09 y contención R17

Revisor: agente backend, autor distinto del catálogo, política y limitadores. Se leyeron catálogo, política, FeatureGate, limitadores globales, dependencia por ruta, métricas y composición API; se revisó el diff final de las tres llamadas auth. Se ejecutaron 69 casos de catálogo/política/FeatureGate/Redis: backend-policy-review.log/xml. Los hashes posteriores identifican el candidato; no prueban estabilidad antes y después del gate.

Hallazgos corregidos por el autor: la lista sensible omitía rutas reales de subscribe/confirm/MP B2B y checkout legacy, que llegaban a fallback local cuando fallaba Redis. La selección XFF restaba un proxy adicional y podía elegir un valor anterior al último no confiable. El autor agregó rutas financieras, portales e invitación, pruebas de outage, el índice XFF corregido y pruebas de cadenas incompletas o inválidas. También corrigió la fábrica API para no pasar al middleware Redis argumentos exclusivos del middleware local. Se revisó el diff y se repitieron las pruebas tras las correcciones.

Controles observados: Lua realiza INCR y TTL inicial en una operación y no extiende la ventana por solicitud. Las dependencias respetan cinco intentos en 900 segundos y usan contador compartido si hay Redis; la cuenta normalizada se identifica mediante HMAC, sin email en claves o logs. Redis incierto devuelve 503 antes del trabajo sensible; lecturas y logout tienen fallback local acotado, límite de memoria y limpieza bajo lock. Los logs incluyen clase; las métricas declaran su alcance por proceso. El proxy sigue necesitando ingress verificado que impida acceso directo no confiable.

La política B2B rechaza planes o estados desconocidos, past_due y vencimiento explícito; guard y FeatureGate comparten implementación. Timestamps históricos sin zona se interpretan como UTC. Se conserva el caso histórico activo sin fecha, sin crear gracia. Free aprobado: diez clientes, un plan por cliente al día y diez planes globales al día; mensual veinte conserva el contrato previo. Los precios existentes permanecen 159/479/979 MXN y 79 MXN individual, con centavos enteros y moneda/periodo canónicos. Starter uno y Pro cinco mensuales quedan separados del diario B2B. Las altas Google y registro inicializan membresías mediante el parámetro explícito; GET/listado no lo hace.

No quedan observaciones altas o críticas en esta contención revisada. R17 sigue pendiente de Redis real, cuatro workers, carga e ingress desplegado. B17 sigue pendiente de reserva atómica B2B para día global, día de cliente y mes, timezone America/Mexico_City y pruebas multiworker. QA integra el gate de auth posterior a los tres cambios puntuales con R03. La ampliación posterior de firma y gate de esquema API tiene evidencia R03 propia; este documento no la acepta por anticipado.
