# Cleanup manual: unidades y fallo visible

El script existente comparaba `RefreshToken.expires_at` (Float de segundos Unix) con un datetime. Sobre seis filas sintéticas, SQLite borró las seis cuando sólo dos superaban el corte; PostgreSQL falló y el catch informó cero. El nombre histórico correcto de la otra tabla es `auth_audit_log`; no hubo que renombrarla. [Reproducción y fuentes autor](evidence/cleanup-tokens-author-source.json).

`scripts/cleanup_expired_tokens.py` ahora convierte el corte de tokens a epoch y usa la columna UTCDateTime tipada para auditoría. El predicado sigue siendo estrictamente anterior al corte: la fila exactamente en la frontera se conserva. Revocación no modifica esa condición. Se preservan los parámetros existentes de30 días para tokens y90 para auditoría; corregirlos técnicamente no aprueba una política legal de conservación ni instala un scheduler.

Cada operación usa una transacción y devuelve el rowcount sólo después del commit confirmado. Un fallo de ejecución/commit lanza `CleanupFailure` con código estable; logs y excepción pública omiten SQL, parámetros, URL y traceback. Si se pierde el acuse después de un commit aplicado, no informa éxito ni cero. Un fallo previo al commit revierte el borrado. El programa termina1 ante fallo y no inicia el segundo paso si falla el primero. Los dos pasos conservan transacciones independientes: si auditoría falla después de tokens confirmados, ese primer commit permanece.

La ejecución manual sigue siendo `python -X utf8 scripts/cleanup_expired_tokens.py` sobre un destino propio previamente comprobado y configurado. En esta ejecución sólo se invocó CLI contra SQLite temporal controlada por el test y conexiones PostgreSQL UUID aisladas; no se ejecutó el comando con el destino por defecto ni sobre producción. No se crearon cron, tareas programadas ni retención automática nueva.

Validación autor:17 casos verdes (incluidos dos PostgreSQL con rol app restringido, UTC/México), después de17 rojos. Revisión QA independiente:23 verdes en SQLite/CLI (15 autor y8 nuevos), con commit rechazado, commit aplicado/acuse perdido, rowcount desconocido, rollback y exit0/1 reales. Las cuatro fuentes cleanup quedaron estables; [revisión QA](evidence/cleanup-unit-independent-source.json). El seguimiento PostgreSQL independiente sobre el nuevo contrato26 espera su freeze; no se atribuyen estos gates al esquema futuro.
