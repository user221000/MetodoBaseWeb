# R04: aislamiento y operación del candidato local

La revisión `20261018_tenant_isolation` conserva23 tablas y activa ENABLE/FORCE en17 familias de tenant. Las seis tablas de control se mantienen fuera de RLS con autorización/predicados explícitos, según `evidence/backend-r04-policy-matrix.md`. No se declara aislamiento universal. Una política adicional desconocida aborta la migración; ausencia de tenant, NULL o cadena vacía no concede filas.

Cada transacción y worker usa identidad persistida y SET LOCAL; callbacks e invitaciones válidas enlazan un sujeto verificado sin cambiar una sesión ya acotada. El espacio personal del profesional usa su propio ID. Startup web y API comprueban estructura, revisión, políticas, FORCE y helper invoker, y rechazan superuser/BYPASSRLS o pertenencia directa/indirecta a un propietario de tablas. Cambiar banderas, añadir una política permisiva o restaurar el helper como SECURITY DEFINER impide servir tráfico.

Producción requiere dos URLs explícitas: `DATABASE_URL` para la aplicación y `MIGRATOR_DATABASE_URL` para el comando de migración. Host, base y usuarios deben ser explícitos, los destinos coincidir y los roles diferir. Sólo se admiten opciones TLS revisadas en query; no overrides de host, puerto, base, usuario, service u options. La CLI abre y libera un engine propio sin sustituir el pool ni el entorno de la aplicación. `entrypoint.sh` retira la credencial migradora antes de ejecutar el servidor. Los ensayos locales pueden seguir usando DATABASE_URL explícita. No se muestran valores en logs.

Preparación de despliegue pendiente de autorización: inventariar ownership/roles/políticas, obtener backup íntegro y ensayo de restore, provisionar rol migrador y rol app con sólo DML/uso de secuencias, verificar variables sin imprimirlas, ensayar migraciones en staging y promover el mismo digest probado. Una política desconocida o colisión histórica requiere reconciliación explícita. El backup PostgreSQL completo bajo FORCE necesita un rol de respaldo autorizado que pueda leer todo; el rol app no sirve como sustituto. No agregar bypass al runtime para facilitar migración o respaldo.

Rollback no desactiva RLS automáticamente ni ejecuta downgrade destructivo: exige versión compatible y restore previamente verificado. R03 de22 tablas y preparación de23 conservan sus contratos por revisión; un arranque actual no acepta una revisión histórica. No se aplica este documento como orden de producción.
