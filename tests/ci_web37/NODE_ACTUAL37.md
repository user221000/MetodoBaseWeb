`node-current37.json` enumera13 comandos,147 ejecuciones y28 archivos directos o
transitivos. Se exige el nombre y orden exactos de cada criterio, éxito Booleano,
contadores enteros, fuentes previamente fijadas y ausencia de fallos. Las seis

`run_web.py --suite node` conserva por separado los51 comandos,925 ejecuciones y

los55 casos de browser_session31. Su prefijo de fixture sí se importa donde los

sus tests Python reales; no se presentan como programas Node independientes.

Las entradas de este inventario cubren transporte, estado y DOM mínimo de cuenta37;
estado, DOM, navegación y bootstrap clásico de notificaciones27/36; prueba pública
de correo37; y cuatro conjuntos independientes de límites de autoridad401.
El companion de headers mantiene explícita la adaptación temporal de tres de los

`ci_web37_offline.cjs` mantiene bloqueados procesos, sockets, HTTP, fetch y motores
de navegador. Dos lecturas Git usadas por los peers se sustituyen por datos RAW
originales con SHA256 fijos, con sus revisiones6ee27e3c y08de03f3 declaradas en el
inventario. Sólo se admite exactamente `git show <fuente:ruta>` con `encoding=utf8`;
no se inicia Git, no se admiten opciones extra ni se concede otro proceso.
La comparación de los datos originales se conserva. Los mandos de autor
`BROWSER31_SOURCE` y `SEC_BROWSER_SOURCE` se retiran antes del gate para que la
ejecución use el Api actual del checkout.

Los informes públicos de correo poseen un formato distinto: líneas PASS con cada
nombre y un footer tipado. La adaptación es explícita y rechaza omisiones, nombres
duplicados, distinto orden, datos adicionales y contadores de otro tipo. Los peers
usan `rows`; los contratos autor usan `results`. No hay un fallback por contadores.
